# Benchmark artefacts

One directory per experiment. Nothing here was edited by hand — these are the
files the benchmark wrote.

```
<experiment>/<backbone>/seed<k>/
├── config.json      the FULL resolved configuration for that run
├── metrics.jsonl    one JSON object per epoch, per stage, per split
└── bench.json       every benchmark metric, plus meta.device (the machine)
```

| directory | experiment | seeds | controller |
|---|---|---|---|
| `tmaze_corridor32/` | **headline**: `TMaze-v0`, corridor 32, 150 memory epochs | 2 | `lstm`, `gru` both seeds; `supreme` seed 0 only |
| `tmaze_corridor16/` | the easier operating point (saturates) | 1 | yes |
| `carracing/` | the external control, half scale | 1 | no |
| `lambda_sweep/` | loss-weight ablation, corridor 6 | 1 | no |

`REPORT.md` and the `.png` figures in each directory are generated by
`python wm.py report <dir>`.

## Two directory names that are not backbones

- **`baseline/`** holds the *shared V-training stage*, not a model. `cfg.name` is
  `baseline` while the ConvVAE is trained, which is why the directory is called
  that. Its `metrics.jsonl` has the VAE loss curve and its
  `vae_reconstructions.png` is the qualitative check that matters most for this
  study: if the cue colour is not legible in the reconstruction, *V* has thrown
  the signal away and no memory layer could recover it.
- **`supreme-cms`** is the *baseline LSTM* with the Continuum Memory System
  attached — it is an ablation of Hope, not a variant of the baseline.

## What is deliberately absent

**Corridor-16 `supreme` and `supreme-titans`.** A stability fix to the Titans
recurrence (a projection onto a Frobenius ball — see the top README §6 and
`code/Supreme/titans.py`) changed what `supreme` computes. Those two runs predate
it, so they are **not reproducible from the shipped code** and are not presented
here as results. Shipping an artefact the accompanying code cannot reproduce is
exactly the thing a reviewer should object to.

Post-fix runs are identifiable: their `metrics.jsonl` logs `titans_clip_rate`
every epoch. Every `supreme` artefact in this directory has it.

**`attention` at corridor 32**, **`supreme-titans` on current code**,
`SequenceRecall-v0`, the continual-learning protocol, and the corridor sweep were
not run at all. See the top-level README §6.
